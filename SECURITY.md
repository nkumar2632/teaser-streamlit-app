# Local security boundary

- Only this app workspace and its disposable `.model_reference/` checkout were used. The app does not search personal folders or unrelated repositories. The model reference is ignored by the app Git repository, pinned to `94e412ed5bedc03a60b0b86f1146ff80c9f9e195`, checked for changed/untracked/ignored source files and foreign preloaded modules, and has its push URL set to `DISABLED`. The app never edits source-model files.
- Streamlit binds `127.0.0.1`, keeps CORS/XSRF protection enabled and disables usage statistics. There is no public deployment, sportsbook credential flow, account integration, or automated wager placement. User-triggered URL imports make one bounded public HTTPS request to ESPN's scoreboard JSON only; redirects, arbitrary hosts, login pages, and sportsbook URLs are refused. Normal grading makes no network calls.
- Market snapshots, paper runs/results, confirmed game scores, and operator-reported NFL placements/settlements are append-only local JSON in ignored `market_data/` folders. Imported slates cannot specify filesystem paths; record retrieval accepts only generated IDs. CFB final scores join a frozen model run after selection and never enter live bankroll totals. Local history files contain user-entered sportsbook data and should remain on this computer.
- URL results remain in session memory until a separate confirmation action. A confirmed URL snapshot is marked `REFERENCE` and retains source URL, fetched URL, provider, capture time, per-event IDs, displayed odds provider, and corrections. It is never copied into an execution slate or used for live placement/accounting. ESPN's public feed is an external source whose values and availability can change; the operator must review them.
- Screenshot uploads accept only decoded PNG/JPEG images and enforce per-file, aggregate-count, aggregate-size, filename, dimension, and decompression limits. Images are treated as untrusted data. Optional OCR invokes only the repository's fixed Apple Vision script with a fixed executable and argument array; no shell or user-selected command/path is used. It runs locally with a timeout and no cloud credentials. Raw image bytes stay in session memory, use a private temporary file during OCR, and are not retained after confirmation/discard. Confirmed snapshots retain hashes and bounded metadata, not image content.
- Screenshot extraction never saves automatically. The operator supplies the sportsbook, league, and timezone-aware capture time, reviews an editable table, resolves conflicts, and explicitly selects **Confirm EXECUTION Snapshot**. Saved records are append-only `EXECUTION` snapshots. Teaser parsing recognizes only labeled 6-point products; uncertainty stays visible and missing prices remain missing. Neither OCR nor confirmation changes a model card, prior placement record, paper result, or `REFERENCE` snapshot.
- The comparison screen reads stored snapshots only. It classifies manual sportsbook records as `EXECUTION` only when their source and book are explicit; uncertain legacy or screenshot-transcribed records stay unclassified. Matching requires explicit team identity and compatible kickoff, and ambiguous matches remain unmatched. Neither comparison nor ESPN presets invoke the model or alter placement accounting.
- No secrets are required. `.env*`, `.streamlit/secrets.toml`, keys and similar local files are ignored; never put credentials into a slate or source-control files. A downloaded slate contains whatever sportsbook metadata you entered, so handle it as your own local data.
- Manual/JSON inputs are bounded and validated. JSON is parsed as data, with duplicate fields rejected. URL fetches have strict domain/path/query checks, a size limit and timeout, and do not follow redirects. There is no `eval`, pickle/deserialization, shell command built from user input, arbitrary user-selected file path, or upload persistence. User text rendered in HTML cards is escaped. Model source files are read from fixed paths only.
- Results fetches use the same allowlisted ESPN HTTPS path. Scores are reviewed and matched against stored teams and kickoff before immutable confirmation. Ambiguous matches block settlement, and a later manually corrected score takes precedence over an older ESPN capture. Only an explicitly operator-recorded PLACED NFL ticket can generate LIVE P/L, after separate sportsbook settlement confirmation. Ticket terms come from the stored proposal and recheck; missing terms or whole-number pushes require review. Repeated confirmations are checked for duplicate accounting.
- **Residual limits:** The user must verify that manually entered lines, prices, timestamps, final scores, outside placements, and book settlements are accurate. The app has no authentication or certified placement ledger and should remain on loopback. Local history files are append-only but not protected against someone with filesystem access. Recheck is not the model's full placement authorization. A **PLACED** record is an unverified operator report, not evidence that a wager was made. Third-party Python packages are installed from the standard registry; update them deliberately and rerun focused contracts. One upstream source test rewrites a tracked report timestamp; do not run the source's full suite in the pinned reference. See MODEL_PIN.md for recovery history.
